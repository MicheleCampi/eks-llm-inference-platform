## Findings, each to be fixed as code

1. **vLLM CPU KV cache is a fixed 4 GiB, so the 6Gi pod is OOMKilled.**
   vLLM CPU v0.11.2 sizes the KV cache only from `VLLM_CPU_KVCACHE_SPACE`
   (default 4 GiB, `vllm/platforms/cpu.py`), with no CLI flag. The same
   image, command and 6 GB limit answered in Docker (4.88 GiB used), but on
   the node the container was killed right after `GPU KV cache size:
   349,440 tokens`, 8 restarts. Raising the limit to 6900Mi did not fit: the new pod
   stayed Pending (see the cost caps). Fix: the operator passes `env` to
   the container, and the example sets `VLLM_CPU_KVCACHE_SPACE=1`.
2. **Argo CD does not revert a key added out of band.** With selfHeal on,
   `EC2NodeClass default` kept `tags.DriftTest` and `karpenter-nodes` stayed
   Synced/Healthy: the default diff ignores map keys that Git does not
   declare (server-side diff would not see it either: server-side apply
   leaves fields another manager owns). Fixed after the session at
   admission: Kyverno `karpenter-config-from-git` lets only Argo CD and
   Karpenter create or update NodePool and EC2NodeClass.
3. **The runbook had no step to put the Grafana secret value.** Terraform
   creates `llm-inference/grafana-cloud-remote-write` empty (never in
   state). Without the value, ESO reported `SecretSyncedError`, Alloy
   `CreateContainerConfigError`, `monitoring` Degraded. Put live from stdin
   with a token of a dedicated Grafana access policy (`metrics:write`,
   1-day expiry, deleted after the session). Now step 4 of `live.md`.
4. **`kubectl logs -l` reads only 10 lines per pod.** The first search for
   the interruption log found nothing; `--tail=-1` found it.
5. **`root` OutOfSync with every child Healthy.** Seen from bootstrap to
   teardown; cause not yet investigated.
