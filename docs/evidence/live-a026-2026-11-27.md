## Findings

1. **The clock worked; the plan did not leave room for two goals.** Every
   step was compared with the table, both reminders fired, and the billable
   part ended inside the limit, unlike A-025. But E5 plus its clean took
   until apply + 1 h 34 min, past the S3'' start. A goal with a 5-minute
   steady state and a set-up of about 12 minutes does not fit as second
   goal in a 2 h window. Next live: S3'' alone, or first.
2. **An orphan VPC CNI ENI blocks the destroy, and `verify-teardown.sh` did
   not see it.** The script checks what is billable; a VPC, its subnets, ENIs
   and the cluster security group are free, so it printed TEARDOWN CLEAN with
   the VPC still there. Fixed in this change: the script also counts the
   project's VPCs, ENIs with a `aws-K8S-` description and the cluster
   security group, and the runbook says what to do on `DependencyViolation`.
3. **The router overlay places each arm's router on the other arm's model
   node.** Allowed by the overlay (it keeps a router off its own arm's model
   only); recorded for E5 because a router's CPU was shared with the other
   engine. Both arms had it, symmetric, and the failure is a connection close,
   not a latency effect.
